# 真实环境验收

[English](acceptance.md) · [简体中文](acceptance.zh-CN.md)

目标环境接入需要：根地址或 Console API 地址、准确镜像版本、具备工具读取与应用编辑权限的测试账号、可用运行模型，以及认可的业务测试数据。密码和 Key 只在插件安全输入框中填写。

## P0 接口验证

- [ ] 以镜像标签或管理员信息确认实际 Dify 版本；不是 1.14.2 / 1.17.1 时先适配，不尝试冒充版本。
- [ ] 登录产生 Cookie/CSRF，工作空间切换和权限验证正确。
- [ ] 同步内置、API、工作流、MCP；同名工具身份不同，无权限不显示为空目录。
- [ ] 使用真实参数读取工具详情，核对嵌套结构、动态选项和输出。
- [ ] 导入 `examples/workflow`、读取依赖、草稿运行、发布，并检查实际应用。
- [ ] 导入 `examples/chatflow`、多轮运行、检查独立会话与 message_end。

## 五项业务验收

1. 需求只描述业务目标。Agent 自动找到至少两个已有工具，记录真实身份与参数来源，连接输出并通过固定断言。
2. Chatflow 信息不足时追问；后续带上下文调用真实工具。不同案例独立会话，修改 DSL 后重开会话。
3. 更改工具参数或删除工具，刷新后不继续使用旧定义；依赖变化导致重新测试。
4. 改造现有应用只修改测试副本。取消覆盖确认时原应用保持原样；他人修改后原应用更新被阻断。
5. 在模型调用、导入、发布时分别断网或取消。恢复不能重复创建应用、重放未知发布或覆盖未知更新。

## 发布门槛

- [ ] 所有生成节点在实际目标版本导入并运行成功。
- [ ] Workflow 和 Chatflow 的真实运行报告、用例摘要、候选摘要与工具来源一致。
- [ ] 参数/引用错误能修复；权限与凭据缺失停止，不消耗无效修复轮数。
- [ ] 用例不可弱化；修改本地候选、远端草稿、环境依赖后拒绝旧报告发布。
- [ ] 原应用有确认、冲突检查、原始 DSL 备份及发布记录。
- [ ] Windows x64、Linux x64、macOS ARM64 原生引擎测试与 VSIX 安装完成。
- [ ] 脱敏报告存档后才更新兼容矩阵；模拟报告始终标注为模拟。

测试须在获准的业务环境进行。报告可能包含业务输出，勿将未经脱敏的原始报告提交至开源仓库。
